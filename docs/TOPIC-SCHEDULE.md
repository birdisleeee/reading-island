# AI 定时发起共读议题

设置 → 议题设置。首版为每个已登录读者提供一个可启用/暂停的定时规则，默认暂停。

1. 先在 AI 设置连接自己的模型，或者配置自己的 Webhook Agent。
2. 选择每天一次或每周一次、星期、时间和标准时区（默认 `Asia/Shanghai`）。
3. 选择全部可读书籍、正在阅读的书籍、指定分组或指定书籍。
4. 填写希望怎样发起议题，例如“从原文找一个有意思的细节，提出问题，邀请我回应”。
5. 勾选启用并保存，页面显示下一次执行时间；取消勾选并保存即可暂停后续执行。

每次轮选范围内一本有可读原文的书，创建一个独立议题并请求 AI 开场。网站显示任务指令为“定时任务”，随后是 AI 回复。人物预设继续用于模型型开场。最近执行记录可在议题设置查看；新回复进入现有未读机制。

## 后端与费用

使用部署者自己 Cloudflare 账户中的现有 `ReadingLibraryDO` Alarm，不用保持网页、电脑或手机开启，也无需新增 Cron、服务器或共享作者账户。每位读者的定时配置、执行记录和书籍范围都在自己的 owner 数据空间。

Alarm 唤醒对象后读取已保存规则；一次只设置一个下一次闹钟。[Cloudflare 官方说明](https://developers.cloudflare.com/durable-objects/api/alarms/)解释了这一机制与至少一次唤醒语义。项目以存储事务消耗每次到期身份，再使用稳定 thread/turn/delivery 身份创建议题，重复唤醒不重复付费生成。

启用后，每次执行使用自己的模型 API 余额及自己的 Cloudflare 资源。先保存规则会安排未来执行；保存时不会立即调用模型。暂停只停止后续任务，不撤销已发出的请求。没有可读书籍时跳过；原件保留但不能提取正文的 PDF/Kindle 文件不作为定时候选。

## 时间与失败边界

- 按规则时区计算每日/每周的下一个本地时间。夏令时不存在的分钟跳过；重复的本地分钟仅执行首次。
- 平台和上游可能延迟，不承诺秒级准点。延迟超过6小时的旧任务记录为跳过，再安排下一次；不会集中补发一批过去的付费请求。
- 模型失败或请求结果未知时，不自动重复生成。执行记录保留失败/处理中状态；重新开启规则也不会重放已消费的到期身份。
- 进程在发请求前后中断时，某次记录可能保持“准备中/处理中”，需要维护者核查；优先避免未知结果下重复扣模型额度。后续任务仍按已保存的下一次闹钟运行。
- 这里是共读网站内部的议题任务，不是邮件、推送通知或通用 Agent 任务系统。

验证使用真实 workerd SQLite/R2/Alarm 和合成模型替身，覆盖重复唤醒、暂停、范围隔离、人物消息顺序和失败边界；未使用真实付费模型或在正式 CF 账户验收定时执行。
