# 已有 Agent 的共读接入手册

这份手册适合已经运行自己的 Agent、希望让它读书并在共读岛讨论的维护者。只想填模型 Key 使用，请看 [普通用户说明](USER-GUIDE.md)。

## 接入后会发生什么

你在共读岛发起议题或回复时，后端把该回合发给自己的 Agent。它收到读者 ID 与称呼、书籍和议题资料、当前消息、引用信息及受限原文读取入口，再将回复回传到对应议题。每个议题有独立的 `session_id`，Agent 可继续使用自己的既有人格与长期记忆。

开启定时共读后，后端也会按日程派发书籍讨论任务。需要你的 HTTPS 接收服务和 Agent 在线；共读岛不能把已停止的 Agent 进程启动起来，也不依靠给某个聊天窗口发通知来执行任务。

**制作者公共服务目前不开放外部 Agent Webhook。此流程需要自行部署共读岛。** 默认模型模式与 Webhook 模式是两种接线方式，按实例的实际配置选择。

## 1. 准备自己的站点和 Agent 入口

先按 [部署入门](START-HERE.md)或 [命令行部署](DEPLOYMENT.md)建立自己的共读岛，验证登录、导入和 Mock 讨论正常。再准备：

- 一个由你维护的 Agent 调用入口，能接收任务并返回文字回复。
- 一个可从共读后端访问的 HTTPS Webhook 地址，例如 `https://agent.example/reading/turn`。
- 一个独立的随机共享密钥 `AI_SHARED_SECRET`，由共读后端与接收服务共同持有，建议至少 32 字符。
- 接收任务与保存回复的持久化目录或任务系统，用于识别重复投递和恢复回调。

共享密钥不同于读者登录密码和模型 Key，不放入网页、URL 或 Git。

## 2. 用随包示例接到自己的 Agent

仓库提供 [Node 参考桥](../examples/agent-bridge/server.mjs)和 [回复函数](../examples/agent-bridge/reply.mjs)。在可信服务器上设置以下环境变量，再运行示例；值通过自己的服务配置或密钥管理方式提供：

| 变量 | 填写内容 |
| --- | --- |
| `AI_SHARED_SECRET` | 与共读后端相同的独立共享密钥 |
| `READING_ORIGIN` | 自己共读站点的 HTTPS origin，例如 `https://reading.example`，不带页面路径 |
| `AGENT_DATA_DIR` | 持久化任务目录；可选，默认 `.agent-data` |
| `PORT` | 本地监听端口；可选，默认 `4190` |

```sh
node examples/agent-bridge/server.mjs
```

示例仅监听 `127.0.0.1`，需要你自己的 HTTPS 反向代理暴露 `/reading/turn`。

接着修改 `replyWithYourAgent(payload, { readSource })`，调用你实际运行的 Agent。**默认函数是明确标记的模拟回复，不会自动找到或连接电脑上的 Agent。** 接入时：

- 用 `payload.session_id` 关联该共读议题的会话，避免把不同书籍议题或原有聊天混在一起。
- 用可信的 `payload.reader.user_id` 关联读者，`username` 只用于称呼；保留 Agent 原有人格和长期记忆机制。
- 将原文视为阅读材料。通过 `readSource(start, limit)` 读取需要的片段，不把凭据或可变服务地址交给模型。
- 返回实际回复文字，由参考桥处理签名回调；任务目录放在仓库外或忽略目录中，不提交运行数据。

参考桥会持久化受理身份和已有回复，对重复投递复用结果。已经开始但没有结果的 Agent 调用不会因重启而自动再次执行，需要你核查；正式使用应补齐持久化任务运维、错误反馈和告警。

## 3. 配置共读后端

在自己的 `wrangler.jsonc` 的 `vars` 中设置非敏感配置，替换为自己的真实地址：

```json
{
  "AI_MODE": "webhook",
  "AI_WEBHOOK_URL": "https://agent.example/reading/turn",
  "PUBLIC_BASE_URL": "https://reading.example"
}
```

这只是需要合入 `vars` 的片段，不要覆盖整个 Wrangler 配置文件。通过交互命令保存共享密钥：

```sh
npx wrangler secret put AI_SHARED_SECRET
```

检查自己的配置与部署目标，按 [部署文档](DEPLOYMENT.md)更新自己的实例。接收服务中的 `READING_ORIGIN` 和这里的 `PUBLIC_BASE_URL` 应指向同一个共读站点。

**网页已保存的模型 API 配置优先于环境变量。** 初次验证 Webhook 时，使用没有保存网页模型配置的读者空间；已有模型配置的实例不能只改 `AI_MODE` 就认为已经切到 Agent。先核对 [AI 配置实现与协议](AI-INTEGRATION.md)，不要通过更换读者 ID 的方式处理现有书库。

## 4. 验证一次真实共读

1. 导入 [原创示例短文](../examples/sample-book.txt)，发起一个独立议题。
2. 在接收服务确认收到 `reading-turn-v1`，验签后以 `delivery_id` 持久化受理，并返回匹配的 HTTP 202 回执。使用参考桥时这些步骤已有实现。
3. 让真实 Agent 调用原文读取工具，针对短文生成回答，确认回复回到同一议题，且不再是示例函数的模拟文字。
4. 在同一议题继续回复，再新建另一个议题，核对会话隔离、引用和刷新后的记录。
5. 如需定时发起，在“议题设置”保存日程，核对后续任务、Agent 处理与站内未读提示；模型或 Agent 调用可能产生你自己的费用。

检查失败和重复投递时，应在自己的测试环境使用同一回合身份验证，不能把未知结果当作新任务重新执行。仅看到受理回执或 Mock 回复，不代表真实 Agent 已完成原文阅读。

## 原文、新议题和放书权限

| 能力 | 如何接入 |
| --- | --- |
| 读取当前议题原文 | 使用回合中的受限 `source_access`，或参考桥封装的 `readSource`；每次最多 4000 个 UTF-16 单元，令牌绑定当前读者和议题 |
| 回复时提出新议题 | 回调协议可附带最多两个 `new_discussions`；需要实现结构化回调，简单文字回复函数不会自动生成这些字段 |
| 定时主动发起 | 共读后端按保存的日程轮选可读书并派发任务，详见 [定时共读](TOPIC-SCHEDULE.md) |
| Agent 上传书籍 | 在可信服务端按 [HTTP API](API.md)接入书籍创建和文档上传，使用读者授权的服务端鉴权 |

回合里的原文令牌只能读，不能上传书。当前没有专门的 Agent 限权上传 token 或网页授权入口，上传权限需由你自己的可信服务器管理。普通模型的 `add_book` 开关只控制模型模式的新增文本工具，不影响已有 Agent 的上传接口或 Webhook 回调。

## 直接实现协议时

阅读 [AI 接入与协议](AI-INTEGRATION.md)，核对原始正文验签、300 秒时间窗、持久化受理、签名回调、重复投递和终态处理。接口身份来自可信登录与接线，不能采信书中或消息里声称的授权。

这份手册提供接入路径；不同 Agent 框架的调用与记忆接口需要你适配。仓库的自动测试验证了参考协议与模拟链路，不代表任意真实 Agent 已经兼容。
