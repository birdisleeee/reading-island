# 共读岛公共服务适配器

这是运营与部署文档。想申请并使用制作者提供的网页 / APK，请看 [普通用户使用说明](../docs/USER-GUIDE.md)。

独立于默认单人部署的可选托管入口。目标域名 `reading.nyachu.site`，提供网页、APK、注册申请、人工审核与限额存储。申请默认待审核、零额度。用户填写自己的模型 Key，服务端按用户以 AES-GCM 加密保存；运营者不提供公共模型余额。

## 审批和额度

Android 应用内更新候选和发布产物配对流程见 [客户端说明](../android-app/README.md#应用内更新)。更新元数据 `/download/android-update.json` 和 APK 下载均不要求账号批准；它们不授予书库访问权限，也不消耗模型配额。新版 APK、对应元数据和旧版网页提示应在同一已审核服务版本中发布。1.1.1（3）已发布，旧安装包用户需手动覆盖安装一次，此后可在应用内检查新版。

沿用同系列公共服务的申请、审核、预算和扩容规则：初始最多 3 个 active 账号、30 个注册账号、10 个待审核申请，公共接口每日 3000 次。待审核和暂停账号不能进入书库；已有会话实时检查状态。运营入口 `/owner` 使用独立密钥，不占每日业务请求预算。

| 额度 | 每账号建议值 | 总分配预算 | 计量方式 |
| --- | ---: | ---: | --- |
| 书籍 | 20 | 60 | 包含归档和未完成导入的预留 |
| 议题 | 200 | 600 | 包括已结束的历史议题 |
| 存储 | 100 MiB | 300 MiB | SQL UTF-8、原件、冻结全文、分块、manifest、封面，每记录/对象加 256 字节预留 |
| 每日服务请求 | 1000 | 3000 | 书架访问、保存讨论及每次模型 HTTP 转发（包括测试、失败和工具续答）；UTC 零点，即北京时间 08:00 重置 |

AI 使用用户自己的 Key，不设累计调用次数额度。历史 aiCalls 配额字段被忽略，不需要重审账号或重写数据；累计调用统计仅供诊断。短时模型转发防刷为每账号每分钟120次，后台自主议题同样受每日账号和全局预算约束。

运营者批准时可在总预算内调整书籍、议题、存储和每日服务额度。扩容申请填写新的总额度，申请本身不授予额度。暂停保留数据和预算。书库按可信 UUID 使用独立 SQLite DO，原件和冻结文本按账号、书籍前缀隔离存入该 DO 的 SQLite 分块表。SQL 写入和对象预留在同一 DO 内校验；失败上传保留预留，同键重试不重复计量。逻辑配额不等于平台索引、日志和网络等实际计费；同一平台账户的服务上限仍共享。

## 部署与维护

开放书库搜书工具运行在同一个公共 Worker 中，不增加常驻引擎、定时爬虫或存储镜像。每账号每日 10 次新检索、3 次下载尝试、单文件 10 MiB，并继续受原有审批及书籍/存储限制；不会自动扩大总分配预算。详见 [开放书库说明](../docs/BOOK-CATALOG.md)。

1. `npm ci && npm run build`，先验证本地申请、审核与书库。
2. 修改本目录 `wrangler.jsonc` 中 Worker、域名和速率限制 namespace ID，使用独立新资源；公共版使用已有可用的 SQLite DO 能力，不要求额外激活 R2。
3. 为本配置设置不同的随机 Secret：INTERNAL_KEY、OWNER_KEY、SESSION_SECRET，每个至少 32 字符。不配置默认读者密码或共享模型 Key。长期保留 SESSION_SECRET，变更它会使已有模型 Key 不可读。
4. 本地验收后 `npx wrangler deploy --config public-service/wrangler.jsonc`；缺少密钥时服务拒绝开放。
5. 设置环境变量 PUBLIC_SERVICE_URL、PUBLIC_OWNER_KEY，运行 `node public-service/bootstrap.mjs`，只为首次空服务初始化政策；既有实例拒绝重复初始化。
6. 在 `/owner` 审核真实申请。本地演示账号和数据不能复制到生产。
7. 按 `../android-app/README.md` 构建 APK，复制到构建产物 `dist/assets/download/reading-island.apk`，与静态资源一同发布，下载入口 `/download/app.apk`。

升级前备份公共代码、审批状态和存储，保留既有绑定、迁移及密钥；回滚不删除 namespace。默认自部署配置保持独立。公共版不启用 Agent Webhook；自部署版已有 Agent 接口保持。未配置模型时显示明确的 Mock 演示；真实兼容性由使用者连接测试验证。定时任务默认关闭，运行时仍检查审批、每日服务额度和防刷。暂停取消 Alarm；重新启用后需重新保存定时计划。

会话使用 HttpOnly、Secure、SameSite=Strict Cookie。注册、登录、下载和业务有请求体上限及限流。运营密钥不可放入 URL、APK 或仓库。申请不触发通知。

注册保存账号、称呼、选填通知邮箱和密码哈希；密码允许任意非空值，最多128字符，申请用途不再收集。待审核页面显示“待审核批准额度中”，不展示尚未分配的零额度。原有登记资料不自动改写。获批后保存书籍、讨论和加密模型设置。AI 调用会将共读上下文发送给用户选择的模型服务商。请只上传有权使用的内容，并联系运营者处理账号或数据删除。
